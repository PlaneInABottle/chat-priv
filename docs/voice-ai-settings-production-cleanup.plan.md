# Voice AI Settings Production Cleanup - Implementation Plan

## Problem and Success Criteria
- **Tier / risk:** Major, production-bound, medium-high risk. The frontend change is localized but touches the complete Voice AI administration surface; the runtime change affects an isolated production worker and must preserve the host trust boundary.
- Remove the `Primary goal` control and all goal-derived draft-builder behavior without changing persisted Voice Agent records, the Voice Agent API, release behavior, or unrelated product “goal” concepts.
- Make every Voice AI settings/admin string resolve from aligned English and Turkish source keys. In Turkish, none of the reported English text or other Voice settings fallback text remains.
- Preserve the current form hierarchy after removal: the builder contains tone, business context, boundaries, and its draft action in that reading order; no visual redesign or new workflow is introduced.
- Start `kozmopath-voice` using a locked, root-provisioned Python environment that the password-locked `kozmopath` account can read and execute without gaining checkout or host write privileges.
- Validate frontend behavior, locale parity, production assets, worker registration/readiness, Turkish browser behavior, web health, and all PM2 roles before rollout is accepted.

## Approach
Use two independent, reviewable behavior boundaries.

1. Keep draft generation local and remove only its goal dimension. Delete the goal state/control/helper and goal locale subtree, update builder description/layout, and generate the remaining instruction sections through locale templates rather than English literals. The generated draft remains the ordinary editable `prompt`; therefore no API, model, migration, release, or backward-compatibility change is needed. Existing saved prompts—including text that happens to say “Primary goal”—must not be rewritten.
2. Treat English `VOICE_AI` as the canonical key shape and bring Turkish to exact parity while reviewing every rendered key and raw dynamic label used by this route and its two siblings. Add localized defaults and enum/status formatters only where text is application-owned; preserve customer data, agent names, inbox names, transcript content, summaries, phone numbers, provider values, and IDs verbatim.
3. Provision dependencies with `/home/mirza/.local/bin/uv` during deployment, not worker execution. Build an immutable root-owned environment at `/opt/kozmopath/voice-agent-<reviewed_commit_sha>` directly (never build then relocate it) from `/usr/bin/python3.12`, and atomically point `/opt/kozmopath/voice-agent-current` at that version. Change the Voice role to execute `/opt/kozmopath/voice-agent-current/bin/python services/voice_agent/agent.py start`. The versioned environment is root-writable and runtime-readable/executable, while `kozmopath` remains non-privileged and the checkout remains read-only. Runner commit, compiled assets, and current venv target are one compatible deployment unit.

The coordinator restores the prior tracked state with `git revert --no-edit "$REVIEWED_SHA"` (creating an auditable rollback commit), then verifies the changed-path list against the backup manifest; do not use reset, clean, checkout discard, or delete unrelated untracked files.
